# 자율 AI 침투 실증 보고서
## — 공격하는 LLM 에이전트 vs 방어하는 파수꾼, 한 집안 네트워크에서 벌인 공개 실험

작성일: 2026-11-06 (KST) · 작성자: 로이(방어측 파수꾼) · 의뢰: 네트워크 소유자
대상: 본인 소유 시스템 간 실험. 모든 공격은 소유자 승인 하에 수행됨.

---

## 1. 이 실험은 무엇인가

**ARTEX**는 LLM(거대 언어 모델)이 직접 침투 테스트를 수행하는 오픈소스 자율 에이전트다. 사람이 수동으로 하던 "정찰 → 열거 → 인증 → 취약점 확인" 과정을, 계획 수립 에이전트(planner)와 실행 에이전트(worker)가 나눠 맡아 사람 개입 없이 돌린다.

이번 실험에서는 공격수(ARTEX)에게 "직통으로 들이받지 말고 여러 갈래로 돌아가서 침투하라"고 지시하고, 방어수(로이 가드 + fail2ban + 웹 로그)가 그 발자국을 어디까지 포착하는지 대조했다.

**참가자**
| 역할 |主机 | 도구 |
|---|---|---|
| 공격수 | 서하네 (RTX 5060 Ti ×2) | ARTEX 0.4.2 + 로컬 LLM (qwen3:8b) |
| 방어수 | 영거 | roy_guard(실시간 감시·차단) + fail2ban + nginx 접근로그 |

네트워크는 테일스케일(사설 VPN)로 연결. 방어수는 공격수 IP를 화이트리스트에 넣어 **차단하지 않고 관찰만** 하도록 설정했다 — "무엇을 보고 무엇을 못 보는가"가 이 보고서의 핵심 질문이기 때문이다.

---

## 2. 공격 방법 3갈래 (실험 설계)

| # | 방법 | 의도 |
|---|---|---|
| M1 | HTTP 정찰 | 웹 서버 배너·기본 페이지·흔적(robots.txt 등) 수집 |
| M2 | 서비스 핑거프린팅 | 열린 포트(80/22/3900/8086)의 배너·핸드셰이크 지문 수집 |
| M3 | 시그니처 우회 검증 | 서로 다른 User-Agent로 같은 요청을 나눠 보내, 고정 시그니처 탐지가 UA 위조를 뚫리는지 확인 |

전 방법 모두 비파괴·초당 1회 이하 요청 제한.

## 3. 실험 중 생긴 진짜 사건 — 자율 에이전트의 병목은 LLM이다

처음 붙인 LLM(라우터 경유 모델)은 답변은 하는데 **도구 호출(tool call)을 구조화된 형식으로 내보내지 못했다.** "bash를 쓰겠습니다"라고 *글자로* 쓸 뿐, ARTEX가 기대하는 `tool_calls` 필드는 비어 있었다. 결과: 워커 전원이 "생각만 하고 행동 못 함" 상태에 빠져 3분 만에 전부 막혔다.

도구 호출을 제대로 지원하는 로컬 모델(qwen3:8b)로 바꾸자 즉시 풀렸다.

> **교훈**: 자율 에이전트 성능의 병목은 모델의 '지능'이 아니라 **도구 호출 규약을 정확히 지키는 출력 능력**이다. 추론만 하고 행동을 못 옮기는 모델은 에이전트에게 무용지물이며, 이는 ARTEX 공식 문서도 경고하는 지점이다.

## 4. 대조 결과 — 공격 로그 ↔ 방어 로그

(시각은 KST. 공격수 발 요청은 모두 방어수 웹 로그에 남음.)

| 시각 | 공격수 행동 (ARTEX 로그) | 방어수가 본 것 (nginx 로그) |
|---|---|---|
| 11:44 | 작업 3개 생성, 시드 의도 배정 | — |
| 13:59 | 워커 3개 의도 수령, 가동 개시 | — |
| 15:22 | planner "계획 완료" | — |
| 15:23 | 첫 정찰 요청 | `HEAD /` — Chrome UA + Java UA **동시 2종** |
| 15:29–15:30 | UA 회전 실행 | `HEAD /` — Chrome + **Dalvik(안드로이드) UA** |
| 15:46 | UA 미세 변형 | `GET /` — Chrome/127.0.0.**1** (아까와 다른 변형) |
| 16:03–16:07 | 열거 단계 진입 | `HEAD /api/config` ×4 → 404 |
| 16:11–16:12 | 감사 로그 경로 탐색 | `HEAD /auditlog` — **CustomUA/1.0**, Firefox UA |

**관찰 포인트**
1. **UA가 매번 바뀐다.** 같은 대상에 Chrome → Java → Dalvik → CustomUA를 섞어 쓴다. 고정 문자열 일치 방식의 WAF 룰은 이걸 못 잡는다.
2. **그래도 행동은 남는다.** `HEAD /api/config`, `HEAD /auditlog` 같은 "사람이 잘 안 치는 경로"의 반복, 그리고 라운드 간격 없이 이어지는 요청 — 이게 행동 기반 탐지의 먹잇감이다.
3. **속도는 느리다.** 초당 수십 건이 아니라 분당 몇 건. 레이트(속도) 기반 탐지만 쓰면 놓친다. ARTEX류는 "느린 사람 같은 공격자"로 온다.
4. 방어수(로이 가드)는 이 기간 동안 **정확히 관찰만** 했다. 화이트리스트가 없었다면 UA 룰(artex-enrich/norma)과 속도 룰 중 어디에 걸렸을지 — 다음 실험 과제다.

## 5. 한계와 솔직한 고백

- 방어수는 공격수를 화이트리스트로 보호한 상태다. "실전이었다면 차단됐을까"는 미결이며, UA 룰 기준으로는 **안 됐을 가능성**이 높다(에이전트가 UA를 계속 바꾸므로).
- ARTEX의 LLM이 로컬 저사양 모델이라 계획 분해가 얕다(단일 목표 그대로 실행). 더 큰 모델이면 더 깊은 체인 공격이 나온다.
- 방어수 로그에 남은 건 전부 "요청" 수준이다. 인증·권한 상승 단계까지 간 건 아직 아니다.

---

## 6. 실전 차단 시연 — 파수꾼이 실제로 물다

관찰 전용이던 방어수의 화이트리스트에서 공격수를 일시 제외하고 발사 실험을 했다.

| 단계 | 결과 |
|---|---|
| 공격수 발사 (`artex-enrich/1.0` UA) | 방어수 웹 로그에 포착 |
| 실시간 차단 판정 | 약 30초 내 `BLOCKED 100.x.x.x :: bad UA 'artex-enrich/'` |
| 출발지 추적 | rdns `attacker-node.tailxxxxx.ts.net` 확인, /24 연쇄 차단 큐잉 |
| abuse 신고 초안 | 자동 생성됨 |

시연 과정에서 배포판 결함 두 건을 실제로 찾아 고쳤다:
1. 로그 테일 루프의 파일 포지션 처리 결함 — 대용량 로그에서 재읽기/스킵이 발생했다.
2. 블랙홀 라우트 명령어 문법 오류 — 차단은 "판정"하는데 실제 차단이 실패했다.

그리고 더 중요한 사실을 발견했다: **블랙홀 차단은 메인 라우팅 테이블에만 걸리고, 테일스케일(VPN) 경유 트래픽은 자체 테이블을 탄다.** 즉 공개망 공격에는 실효, VPN 피어에는 정책(ACL) 수준 차단이 필요하다. 이 시연이 없었으면 배포판은 "차단합니다"라고 쓰면서 실제로는 못 끊는 상태로 나갔을 것이다.

시연 후 화이트리스트·라우트 원복 완료.

## 7. 결론

1. **고정 시그니처(UA 문자열) 탐지는 자율 AI 공격 앞에서 신뢰할 수 없다.** 이번 실험에서 공격수는 한 시간도 안 돼 5종류의 UA를 섞었다.
2. **행동 패턴(경로 선택, 요청 간격, 세션 일관성)은 위조하기 어렵다.** 방어는 이쪽으로 이동해야 한다.
3. **자율 에이전트의 실효성은 LLM의 도구 호출 규약 준수에 좌우된다.** 출력 형식 하나가 실험 전체를 막았다가 뚫었다.
4. 공격은 느리고 조용하다. **로그를 보는 파수꾼이 항상 깨어 있어야 한다** — 이번 실험이 그것을 증명했다. 파수꾼은 자지 않았다.
5. **차단 메커니즘은 경로별로 달라야 한다.** 라우트 블랙홀은 공개망으로 들어오는 공격에 유효하지만, VPN(테일스케일) 경유 트래픽은 자체 라우팅 테이블을 타므로 블랙홀로 안 끊긴다 — 시연에서 실측으로 확인했다. VPN 피어는 ACL/정책 수준 차단이 필요하다.
